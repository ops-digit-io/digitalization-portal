# 16 — Frontend (shadcn/ui)

The portal is built on **shadcn/ui** — Radix UI primitives styled with Tailwind,
with component source copied into the repository rather than installed as a
dependency.

## 16.1 Why shadcn

| Property | Consequence for this portal |
|---|---|
| Source lives in `components/ui/` | Component changes are reviewable pull requests, like every other artifact in this system |
| Not a dependency | No upgrade treadmill, no breaking changes arriving from upstream |
| Unstyled primitives underneath | Corporate branding is a token change, not an override fight |
| Accessibility from Radix | Focus management, keyboard navigation, ARIA, portalling — the genuinely hard parts |
| Large training presence | Relevant when an AI agent implements the build |

A design system such as Carbon or Material would bring its own visual identity,
which the portal would then spend the project overriding. shadcn brings
behaviour and leaves appearance to the token layer.

## 16.2 Setup

```bash
npx shadcn@latest init
```

Answers: TypeScript yes, style `new-york`, base colour `slate`, CSS variables
yes, `app/globals.css`, alias `@/components`.

Install exactly these. Nothing else from the registry is needed, and adding
components speculatively creates surface to maintain.

### Stage colour discipline

Stage accents identify stage and nothing else — the badge on a card, the swimlane
header, the gate timeline node. Never buttons, never emphasis, never decoration.
The moment stage colour appears where it isn't communicating stage, it stops
communicating stage.

Light mode is the default. Shop-floor devices are used in bright environments.

## 16.4 Portal components

### `GateTimeline`

The signature element of the use-case page. Eight nodes; the whole lifecycle
position readable at a glance, which is the question everyone opens the page to
answer.

```tsx
// components/portal/gate-timeline.tsx
import { Tooltip, TooltipContent, TooltipTrigger } from "@/components/ui/tooltip"
import { cn } from "@/lib/utils"

type GateState = "passed" | "open" | "pending" | "killed" | "parked"

export function GateTimeline({ gates }: {
  gates: { id: string; label: string; state: GateState; on?: string; by?: string }[]
}) {
  return (
    <ol className="flex items-center gap-0" role="list">
      {gates.map((g, i) => (
        <li key={g.id} className="flex items-center">
          <Tooltip>
            <TooltipTrigger asChild>
              <button
                className={cn(
                  "size-3.5 rounded-full border-2 transition-colors",
                  "focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2",
                  g.state === "passed"  && "bg-foreground border-foreground",
                  g.state === "open"    && "bg-background border-foreground ring-2 ring-foreground/20",
                  g.state === "pending" && "bg-background border-muted-foreground/40",
                  g.state === "killed"  && "bg-destructive border-destructive",
                  g.state === "parked"  && "bg-muted border-muted-foreground/40",
                )}
                aria-label={`${g.id} ${g.label}: ${g.state}`}
              />
            </TooltipTrigger>
            <TooltipContent>
              <p className="font-medium">{g.id} · {g.label}</p>
              <p className="text-muted-foreground">
                {g.state === "passed" ? `Passed ${g.on} by ${g.by}` : g.state}
              </p>
            </TooltipContent>
          </Tooltip>
          {i < gates.length - 1 && (
            <span className={cn(
              "h-px w-6",
              gates[i + 1].state === "pending" ? "bg-border" : "bg-foreground",
            )} aria-hidden />
          )}
        </li>
      ))}
    </ol>
  )
}
```

### `ValueFigure`

Encodes a specification rule in the component layer: an indicative figure cannot
be rendered as committed. A developer cannot make this mistake by accident.

```tsx
// components/portal/value-figure.tsx
import { Badge } from "@/components/ui/badge"

type Confidence = "hypothesis" | "indicative" | "committed" | "realized"

export function ValueFigure({ amount, confidence, currency = "EUR" }: {
  amount: number | null
  confidence: Confidence
  currency?: string
}) {
  if (amount === null) {
    return <span className="text-muted-foreground">Needs input</span>
  }

  const formatted = new Intl.NumberFormat("de-DE", {
    style: "currency", currency, maximumFractionDigits: 0,
  }).format(amount)

  return (
    <span className="inline-flex items-baseline gap-2">
      <span className={
        confidence === "committed" || confidence === "realized"
          ? "font-semibold tabular-nums"
          : "font-normal tabular-nums text-muted-foreground"
      }>
        {formatted}
      </span>
      <Badge variant="secondary" className="text-xs font-normal">
        {confidence}
      </Badge>
    </span>
  )
}
```

The confidence badge is never optional. Every value figure in the interface
carries its state.

### `CapabilityGate`

Renders children only when the session holds a capability. Shows the reason
otherwise rather than hiding the action — a user who cannot act should learn who
can.

```tsx
// components/portal/capability-gate.tsx
import { Tooltip, TooltipContent, TooltipTrigger } from "@/components/ui/tooltip"

export function CapabilityGate({
  capability, context, session, children, reason,
}: {
  capability: string
  context?: { plant?: string; gate?: string; useCase?: string }
  session: Session
  children: React.ReactNode
  reason?: string
}) {
  const allowed = can(session, capability, context)
  if (allowed) return <>{children}</>

  return (
    <Tooltip>
      <TooltipTrigger asChild>
        <div className="opacity-50 pointer-events-none" aria-disabled>
          {children}
        </div>
      </TooltipTrigger>
      <TooltipContent>
        {reason ?? `Gate decisions for ${context?.plant} are made by the plant gatekeeper.`}
      </TooltipContent>
    </Tooltip>
  )
}
```

`ScrollArea` per column, horizontal scroll on the container. Filters are
`Popover` + `Command` for searchable lists, `Select` for short ones.

screenshot.

with content.

### Chat — `/`

The landing screen and primary intake surface.

```
┌────────────────────────────────────────────────────────────┐
│                                                            │
│              What's the problem you're seeing?             │
│                                                            │
│   ┌──────────────────────────────────────────────────┐    │
│   │ Describe it in your own words…                   │    │
│   └──────────────────────────────────────────────────┘    │
│                                                            │
│   Or:  Browse portfolio   ·   Use a form instead           │
│                                                            │
│   AI assistant · drafts only, never approves               │
└────────────────────────────────────────────────────────────┘
```

The opening question asks for what the portal needs, not "How can I help?" —
requesters arrive with a problem, not a request.

Loaded skills appear as `Badge` chips so the user can see what the assistant
currently knows how to do. The transparency notice is persistent, not
dismissible: the AI Act obligation is continuous.

Streaming responses render progressively. Dictation is the device keyboard's own;
the portal receives text.

### Triage — `/triage`

Split view, list left and detail right, keyboard-first: `j`/`k` to move, `1`–`7`
to assign lane, `Enter` to accept, `r` to reject with reason. Triage is
repetitive batch work and should be operable without a mouse.

Uses `Command` for the lane picker so it is reachable by typing.

### Handovers — `/handovers`

TanStack Table over shadcn `table`. Accept action opens a `Dialog` with a `Form`
requiring the external reference — the form will not submit without it, because
without it the trail breaks at the boundary.

### Traces — `/traces/[id]`

Agent run replay. `TraceStep` per step in a `Collapsible`. Tools withheld are
listed explicitly with the reason, not omitted.

### Value — `/value`

Three separated figures — pipeline, committed, realized. Never summed into one
headline. Variance table sorted by absolute variance so both directions surface.

## 16.6 Interface copy

Words are design material. Plain verbs, sentence case, no filler.

| Situation | Write | Not |
|---|---|---|
| Gate action | "Request gate decision" | "Submit for approval" |
| After the action | "Gate decision requested" | "Submitted successfully" |
| Insufficient capability | "Gate decisions for DE-ALD are made by the plant gatekeeper." | "Access denied" |
| Empty board | "No use cases yet. Describe a problem to get started." | "No data available" |
| Missing figure | "Needs input" | "N/A" or "0" |
| Indicative figure | "180.000 € · indicative" | "180.000 €" |
| Agent draft | "Drafted by the assistant. Review before merging." | "AI-generated content" |
| Parse failure | "This use case's state section couldn't be read. Open it in GitHub to check the format." | "Parse error" |
| Duplicate found | "UC-2026-0033 looks like the same problem. Link to it, or create anyway?" | "Duplicate detected" |
| Kill confirmation | "Kill this use case? Record what was learned — it stays searchable." | "Are you sure?" |

Errors state what happened and what to do. They don't apologize and they aren't
vague. An action keeps its name through the whole flow: the button that says
"Request gate decision" produces a toast that says "Gate decision requested."

## 16.7 Quality floor

Present, not announced.

- Responsive to 360px
- Keyboard operable throughout; focus rings from `--ring` never removed
- `prefers-reduced-motion` respected — motion is limited to state transitions
- WCAG AA contrast; stage accents checked against both surfaces
- 44px touch targets on mobile
- `Skeleton` on load, never spinners on the board — no layout shift
- `sonner` toasts, bottom-right desktop, top mobile

## 16.8 What not to build

Stated so it is refused rather than forgotten.

| Not built | Reason |
|---|---|
| Per-requester analytics — who submits most, whose demands rate best | Moves the system into EU AI Act employment high-risk territory ([14](14-compliance.md)). Trivially derivable, therefore explicitly prohibited. |
| Merge button | No portal route merges a pull request. The gate boundary depends on this ([13.4](13-security.md#134-the-gate-boundary)). |
| In-portal artifact editing | Documents are edited in the repository under review. In-portal editing would bypass code owners. |
| Portfolio value as one total | Pipeline, committed, and realized are different objects; summing them produces a figure that is arithmetically correct and economically false ([07.9](07-value-model.md#79-portfolio-aggregation)). |
| Notification on every state change | Noise trains people to ignore the portal. Notify on: gate decision requested, gate passed, handover offered, variance escalation. Nothing else. |
